# Polascin.com Agent – Audit, Security & Technical Optimisation

## Project Description

**polascin.com** (alias **portfolio.polascin.net**) is a static portfolio website for Dr. Lubomir Polascin (HTML5 + CSS3 + vanilla JS + one PHP file). It includes:

- Main page (`index.html`) — hero, bio, portfolio (medical app, AI assistant, translation projects), books, contact form
- Subpages (`privacy-policy.html`, `terms-of-service.html`) — legal documents
- Stylesheet (`style.css`) — custom design
- Main script (`main.js`) — navigation, scroll animations, cookie consent (GA4 Consent Mode v2)
- Cookie consent module (`cookie-consent.js`) — GDPR/Consent Mode v2 logic
- PHP handler (`contact-handler.php`) — contact form processing, validation, rate limiting
- Security files (`robots.txt`, `.htaccess`) — HTTP headers, scraper blocking
- SEO infrastructure (`sitemap.xml`, JSON-LD, Open Graph, Twitter Card)
- PWA configuration (`manifest.json`, `favicon.*`)
- FontAwesome 7 (CDN: `https://cdn.jsdelivr.net/npm/@fortawesome/fontawesome-free@7.1.0/css/all.min.css`)

## 🎯 Agent Goal

An autonomous agent for comprehensive technical management and continuous optimisation of polascin.com. The agent performs deep analysis of HTML/CSS/JS/PHP code, runs **Trunk** linting and formatting, verifies security settings (`.htaccess`, HTTP headers, PHP security), checks SEO integrity and structured data, audits accessibility (WCAG 2.1), responsive design, PWA manifest, and performance characteristics. It also proofreads English-language content on the site.

## 📋 Primary Tasks

### 1. Security Audit

- **HTTP security headers in `.htaccess`:**
  - Presence and correctness of: `X-Frame-Options`, `X-Content-Type-Options`, `HSTS`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `X-Permitted-Cross-Domain-Policies`
  - `Options -Indexes` — directory listing disabled
  - `ServerSignature Off`
  - Blocking of `.git/`, `.env`, `*.key`, `*.pem`, `*.sql`, `rate-limit.log`, `contact-log.txt`, and similar sensitive files
  - `contact-handler.php` protection — POST-only access, not directly browsable

- **PHP security (`contact-handler.php`):**
  - Input validation and sanitisation — `filter_input`, `htmlspecialchars`, length limits
  - Honeypot field (`website`) — bot protection
  - CSRF token (HMAC-based, stateless) — `csrf_token` hidden field validated server-side
  - Timing check — minimum 3 s / maximum 1 h between page load and form submission
  - Injection protection — `$suspiciousPatterns` (XSS, `<script>`, `javascript:`, `on\w+=`, `<iframe>`, etc.)
  - Header injection protection — `preg_replace('/[\r\n]+/', ...)` for name and email in headers
  - URL spam detection — messages with more than 2 links are rejected
  - Rate limiting — log file `rate-limit.log`, IP detection (`HTTP_X_FORWARDED_FOR` + `REMOTE_ADDR`)
  - Log files (`rate-limit.log`, `contact-log.txt`) — must be blocked via `.htaccess`
  - `declare(strict_types=1)` — must be present
  - `ADMIN_EMAIL` constant — correct email address
  - `@mail()` — error suppression is acceptable, but return value must be checked
  - `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` headers in PHP — consistent with `.htaccess`

- **JavaScript security (`main.js`, `cookie-consent.js`):**
  - XSS in dynamic DOM generation (cookie banner, `innerHTML`)
  - `localStorage` security — what is stored and how
  - External scripts (Google Analytics) — CSP-compatible loading
  - Google Consent Mode v2 implementation in both JS files

- **`.gitignore` check:**
  - Protection for `.env`, `*.key`, `*.pem`, `.claude/`, `rate-limit.log`, `contact-log.txt`, `config.php`
  - No sensitive files in git tracking

### 2. HTML Audit

- HTML5 structure validity (`<!doctype html>`, semantic elements)
- Presence and correctness of `lang` attribute on `<html>` (`lang="en"`)
- Correct nesting and closing of tags
- `alt` attributes on all `<img>` elements
- `aria-label`, `aria-hidden`, `role` on interactive elements
- `rel="noopener noreferrer"` on all `target="_blank"` links
- Consistency of `id` attributes (duplicates, anchor references)
- Validity of email addresses (`mailto:`)
- Contact form — presence of `action`, correct method (`POST`), honeypot field, CSRF hidden fields, ARIA attributes
- `noindex` meta tag on `privacy-policy.html` and `terms-of-service.html`

### 3. SEO Optimisation

- **Meta tags:** `description`, `author`, `robots`, `theme-color`
- **Robots meta:** presence of `max-image-preview:large`
- **Canonical URL:** correctness and consistency across pages
- **hreflang:** presence of `en` and `x-default` on all pages; `noindex` on legal subpages
- **Open Graph:** `og:type`, `og:title`, `og:description`, `og:url`, `og:image`, `og:locale`
- **Twitter Card:** `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`
- **JSON-LD (Schema.org):** validity of `Person` schema, completeness of `sameAs` field, correctness of `jobTitle`, `alumniOf`, `image`; validity of `WebSite` and `WebPage` schemas if present
- **sitemap.xml:** up-to-date `lastmod`, correct `changefreq` and `priority`, all public pages included
- **robots.txt:** blocking of aggressive scrapers, `Crawl-delay`, sitemap URL pointing to `polascin.net`

### 4. Accessibility (WCAG 2.1)

- Colour contrast — light and dark mode if implemented (min. 4.5:1 for body text, 3:1 for large text)
- Keyboard navigation — visible focus, logical tab order
- Skip link (skip to content) — present for screen readers
- `aria-expanded` on hamburger navigation — correctly updated on toggle
- FontAwesome icons — `aria-hidden="true"` + text alternative
- Form elements (contact form, cookie banner buttons) — `label`, `role`, `aria-label`, `aria-required`
- Portfolio cards — image descriptions (`alt`), readability without CSS
- Colour coding — information not conveyed by colour alone
- `prefers-reduced-motion` — animations disabled per OS setting

### 5. Responsive Design

- All `@media` breakpoints in `style.css`
- Content overflow (`overflow-x`) on narrow screens (320 px–480 px)
- `min-width` values in components — fixed widths may cause horizontal scroll
- Navigation (hamburger menu) — functionality and display on mobile
- Hero section, portfolio cards, books section — scaling on mobile
- Button sizes — min. 44×44 px touch target
- Contact form — usability on mobile
- Cookie banner — display on narrow screens
- `clamp()`, `vw`, and `auto-fit` grid values if used

### 6. Performance & Loading

- Resource loading order — `<link rel="preconnect">` for external fonts/resources (including `cdn.jsdelivr.net`)
- `defer` / `async` on `<script>` tags
- Image sizes — `loading="lazy"` where appropriate; portfolio images and profile photo
- Cache-busting — CSS version parameter (`style.css?v=YYYYMMDD`)
- FontAwesome — loaded via CDN (`cdn.jsdelivr.net`), no local copy in repository
- `og-image.jpg`, portfolio PNG images — file size optimisation

### 7. PWA & Manifest

- **`manifest.json`:**
  - Required fields: `name`, `short_name`, `start_url`, `display`, `theme_color`, `background_color`, `icons`
  - Icon correctness — paths exist, appropriate resolutions (180×180, 192×192, 512×512), separate `any` and `maskable` entries
  - `start_url` — relative or absolute path; consistent with domain
  - `scope` — if present, correct value
  - `description` — present
- **Favicon:**
  - Presence of `favicon.ico`, `favicon.png`, `icon-192.png`, `icon-512.png`
  - `<link rel="icon">` and `<link rel="apple-touch-icon">` in `<head>`
  - `<link rel="manifest">` in `<head>`

### 8. Link Integrity

- All external links in `index.html` (`href` values) — logical correctness
- Consistency of `sameAs` field in JSON-LD with links in portfolio/contact sections
- Social networks and external profiles — correct URL format, presence of `rel="noopener noreferrer"`
- Internal anchors (`#home`, `#about`, `#portfolio`, `#books`, `#contact`, etc.) — targets exist
- Links to `privacy-policy.html` and `terms-of-service.html` — functional from every page

### 9. Cookie Consent (GDPR / Consent Mode v2)

- Correct implementation of Google Consent Mode v2 (`consent default → denied`)
- GA script loaded before consent — verify it does not collect data
- Cookie banner — text mentions GA4, Privacy Policy link works
- `localStorage` key for consent — values `accepted`/`rejected` consistent between `main.js` and `cookie-consent.js`
- `privacy-policy.html` — content aligned with GA4 Consent Mode v2 practice
- Coordination between `main.js` and `cookie-consent.js` — no duplicate logic, consistent API

### 10. Trunk — Linting & Formatting

Trunk is configured in `.trunk/trunk.yaml`. The agent runs Trunk commands and interprets outputs.

**Configured tools:**

| Tool             | Type         | What it checks                                                  |
| ---------------- | ------------ | --------------------------------------------------------------- |
| `prettier`       | Formatting   | HTML, CSS, JS, JSON, Markdown — consistent style                |
| `markdownlint`   | Lint         | `.agent.md`, `README.md` — Markdown structure and style         |
| `trufflehog`     | Security     | Scanning for secrets and sensitive strings in code and history  |
| `oxipng`         | Optimisation | Lossless PNG compression (favicon, portfolio images, PWA icons) |
| `svgo`           | Optimisation | SVG file optimisation                                           |
| `git-diff-check` | Quality      | Trailing whitespace, merge-conflict markers                     |

**Commands:**

```bash
# Check all files (no auto-fix)
trunk check

# Check only files changed since last commit
trunk check --diff

# Auto-format (prettier, oxipng, svgo)
trunk fmt

# Format only changed files
trunk fmt --diff

# Secrets scan only
trunk check --filter=trufflehog

# Markdown only
trunk check --filter=markdownlint
```

**Trunk output procedure:**

1. Run `trunk check --diff` on changed files
2. Classify findings by tool: security (trufflehog) → 🔴, formatting (prettier) → 🟢
3. Apply `trunk fmt --diff` automatically (trivial fix)
4. Trufflehog findings are always 🔴 and **require manual review**
5. Include results in the standard audit report

**Ignored directories (defined in `.trunk/trunk.yaml`):**

- `fontawesome-free-7.1.0-web/` — CDN library (not in repository)

## ✅ Trivial Fixes

The agent **may automatically fix** without explicit approval:

- Typos and grammatical errors in English texts
- Missing `alt` text on `<img>` elements
- Missing `rel="noopener noreferrer"` on `target="_blank"` links
- Inconsistent indentation (whitespace, formatting)
- Missing `aria-hidden="true"` on decorative icons
- Updating `lastmod` in `sitemap.xml`
- Missing `loading="lazy"` on below-the-fold images
- Cache-busting version parameter on `style.css`

The agent **must request approval** before:

- Changes to navigation or section structure
- Changes to cookie consent logic (`main.js`, `cookie-consent.js`)
- Changes to PHP logic (`contact-handler.php`) — validation, rate limiting, email
- Edits to JSON-LD schema (adding/changing fields)
- Changes affecting multiple files simultaneously
- Adding new external dependencies
- Changes to `manifest.json` (PWA scope, icons)

## ⚙️ Agent Workflow

1. **Initialisation:** Load all target files
2. **Trunk check:** `trunk check --diff` — linting, secrets, git-diff-check
3. **Trunk fmt:** `trunk fmt --diff` — auto-formatting (prettier, oxipng, svgo)
4. **HTML audit:** Validity, semantics, attributes, anchors
5. **PHP audit:** `contact-handler.php` security — validation, sanitisation, rate limiting, CSRF, timing, headers
6. **Security scan:** `.htaccess` headers, JS XSS patterns, log file protection, `.gitignore`
7. **SEO analysis:** Meta tags, JSON-LD, sitemap, robots.txt, hreflang
8. **PWA audit:** `manifest.json` — required fields, icons (180/192/512), consistency
9. **Accessibility:** WCAG 2.1 checklist
10. **Responsive design:** Breakpoints, overflow, touch targets
11. **Performance:** Resource loading, lazy loading, cache-busting, CDN preconnect
12. **Link integrity:** External URLs, anchors, social profiles, legal pages
13. **Cookie Consent:** GA4 Consent Mode v2 compliance, `main.js` ↔ `cookie-consent.js` coordination
14. **English proofreading:** All visible English text — grammar, spelling, punctuation, style, professional tone
15. **Auto-fix:** Apply trivial fixes + Trunk fmt outputs
16. **Report:** Results with priority (critical → low)

### English Proofreading Scope (Step 14)

Sections to check: hero tagline, About Me bio, expertise cards, skills section, portfolio project descriptions, digital products, testimonials, nephrology education section, contact form labels, footer, cookie banner, `privacy-policy.html`, `terms-of-service.html`.

**Common issues to look for:**

- Subject–verb agreement, article usage (a/an/the), comma splices
- Inconsistent capitalisation of job titles and medical terms
- Passive constructions that weaken professional tone
- Americanisms vs. British English (site uses American English — maintain consistency)
- Em dash spacing — site uses `—` without spaces (American style — correct, keep consistent)
- Medical terminology — correct spelling: _haemodialysis_, _peritoneal_, _nephrology_, _glomerulonephritis_

**Last proofread:** 2026-05-22 — no issues found. All sections grammatically correct with professional tone.
